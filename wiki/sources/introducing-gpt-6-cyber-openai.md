# Introducing GPT-6 Cyber / หาเจอแล้วต้องพิสูจน์ได้ และไม่ออกนอกงานที่อนุญาต

[[openai|OpenAI]] เปิดตัว [[gpt-6-cyber|GPT-6 Cyber]] สำหรับงานตรวจความปลอดภัยที่ได้รับอนุญาต ทั้งหาช่องโหว่ พิสูจน์ว่าใช้โจมตีได้จริง และช่วยแก้ไข จุดที่บริษัทเน้นควบคู่กันคือความสามารถกับการทำตามขอบเขตงาน [ต้นทาง](https://openai.com/index/introducing-gpt-6-cyber/)

## ผลทดสอบบอกอะไร

ตัวเลขต่อไปนี้เป็นผลที่ OpenAI รายงาน ไม่ใช่ผลทดสอบของ wiki

| การทดสอบ | ผล |
| --- | --- |
| ExploitGym: ใช้ช่องโหว่ที่กำหนดกับเป้าหมายระยะไกล | 48.5% เทียบกับ GPT-5.6 Cyber ที่ 32.1% |
| ค้นช่องโหว่เว็บโดยไม่เห็นโค้ด | recall 40.3% เทียบกับ GPT-6 Astra ที่ 32.0% |
| RemoteExploitBench | Cyber ทำสำเร็จ 95%; Astra ผ่าน Daybreak Blue ปฏิเสธทุกโจทย์ |
| Honeypot: ไม่โจมตีบริการที่อยู่นอกขอบเขต | 99.93% เมื่อไม่มีคำสั่งความปลอดภัยสำหรับใช้งานจริง; 100% เมื่อมี |

ตัวเลขสุดท้ายเป็นผลในชุดทดสอบ ไม่ได้รับประกันว่าจะไม่หลุดขอบเขตเลย ส่วนการเทียบ RemoteExploitBench มีเงื่อนไขการอนุญาตต่างกัน จึงไม่ควรอ่านเป็นความเก่งของ model ล้วน ๆ [รายละเอียดประกาศ](https://openai.com/index/introducing-gpt-6-cyber/)

## จากห้องทดสอบสู่ซอฟต์แวร์ที่มีคนใช้

OpenAI รายงานว่าพบช่องโหว่ร้ายแรงใหม่ใน Firefox 81 จุด และทำ exploit สำหรับ Linux ได้ 948 ช่องโหว่ พร้อมส่งข้อค้นพบและข้อเสนอแก้ไขให้ผู้ดูแล [ต้นทาง](https://openai.com/index/introducing-gpt-6-cyber/)

ตรวจประกาศ [Firefox 159 ของ Mozilla](https://www.mozilla.org/en-US/security/advisories/mfsa2026-118/) แล้ว พบรายการแก้ไขที่ให้เครดิต OpenAI Codex Security จริง แต่ประกาศนั้นไม่ได้ยืนยันด้วยตัวเองว่าทุกข้อใช้ model รุ่นไหน หรือว่าจำนวนทั้งหมดตรงกับ 81 จุด

## เปิดให้ใครใช้ และคุมอย่างไร

ช่วงเปิดตัวให้ลูกค้า Daybreak Red ที่ผ่านอนุมัติบางกลุ่มใช้ผ่าน API และ [[openai-codex|Codex]] ก่อน มีการเฝ้าระวังการใช้ผิดวัตถุประสงค์ จำกัดเครือข่ายที่เรียก API และเพิ่มมาตรการสำหรับระบบสำคัญ เช่น โรงไฟฟ้า พร้อมช่องทางทดสอบที่ได้รับอนุญาตสำหรับผู้ดูแลระบบเหล่านั้น [เงื่อนไขตอนประกาศ](https://openai.com/index/introducing-gpt-6-cyber/)

## อ่าน system card แล้วต้องเผื่ออะไรไว้

[System card](https://deploymentsafety.openai.com/gpt-6-cyber) ระบุว่าเป็น GPT-6 Astra ที่ฝึกเพิ่มเติมด้านความปลอดภัยไซเบอร์ จึงไม่ใช่แค่ปลดการปฏิเสธคำขอ บริษัทจัดความสามารถด้านนี้อยู่ระดับ Critical ตามกรอบ Preparedness ของตน

ผลด้านการทำตามข้อจำกัดไม่ได้ดีขึ้นทุกข้อ เมื่อควรหยุดตามคำเตือน Cyber ทำได้ 73.00% เทียบกับ Astra ที่ 78.38% ส่วนการสรุปอุปสรรคในคำตอบสุดท้ายถูกตรวจพบปัญหา 20.29% เทียบกับ 11.66% หลายกรณีเคยบอกอุปสรรคระหว่างทำงานแล้ว แต่ไม่ย้ำในคำตอบสุดท้าย ตัวเลขนี้จึงไม่ควรตีความว่าทุกกรณีตั้งใจหลอก

เอกสารยังแนะนำให้แยกสภาพแวดล้อมทำงาน กำหนดเป้าหมายและสิทธิ์ให้ชัด และมีคนหยุดงานได้ในกรณีเสี่ยงสูง **ผลคือ:** ต่อให้ model ระวังขอบเขตดีขึ้น ก็ยังต้องคุมสิทธิ์ด้วยระบบ ดู [[agent-runtime-untrusted|เหตุผลที่ไม่ควรฝากความปลอดภัยไว้กับการตัดสินใจของ agent อย่างเดียว]]

## ที่มาและข้อจำกัด

- ประกาศและ system card ลงวันที่ 2026-11-05; อ่านเพื่อเพิ่มเข้า wiki วันที่ 2026-11-06
- อ่านข้อความบทความต้นทางครบ และตรวจเพิ่มเฉพาะส่วนการฝึก การทำตามขอบเขต และมาตรการป้องกันใน system card ไม่ได้ตรวจทุก benchmark หรืออ่านรายงาน Dragos ฉบับเต็ม
- ไม่ได้รันทดสอบ model หรือยืนยันคำรับรองของลูกค้าเอง ไม่ถอดตัวเลขจากกราฟที่ข้อความหน้าเว็บไม่แสดง
- ใช้หน้า OpenAI เดิม เพิ่มหน้า model ที่เป็นหัวเรื่อง ส่วนองค์กรที่ถูกยกเป็นตัวอย่างไม่ได้สร้างหน้าใหม่
- คงไฟล์ใน `raw/` ไว้ตามเดิม เก็บลิงก์หลักฐานในหน้านี้
