# Proof as Raw Data / Proof เป็นแค่ข้อมูลดิบ

**Proof as Raw Data** คือข้อเสนอว่า เมื่อเครื่องสร้าง proof ได้เก่ง วงการคณิตศาสตร์ควรมอง proof เหมือนผลคำนวณตัวเลข คือเป็นวัตถุดิบให้คนเอาไปสร้างทฤษฎี ไม่ใช่เส้นชัย [[3blue1brown|3Blue1Brown]] (ช่อง YouTube สอนคณิตศาสตร์ด้วย animation) เสนอไว้ใน [[never-been-better-time-to-go-into-math-3blue1brown|วิดีโอเรื่องอนาคตของคณิตศาสตร์]] และบอกเองว่ามีคนพูดทำนองนี้มาก่อน

> "I think at this point we should consider proof to be kind of the same as numerical calculation"

## ทำไม proof เคยเป็นเส้นชัย

ส่วนนี้อธิบายว่าทำไมการที่เครื่องพิสูจน์ได้ถึงกระทบใจคนในวงการ ทั้งที่ทุกคนรู้อยู่แล้วว่า proof ไม่ใช่ทั้งหมดของคณิตศาสตร์

คณิตศาสตร์ใช้ proof เป็นตัวแทน (proxy) ของความเข้าใจมาตลอด พิสูจน์ได้ก็แปลว่าเข้าใจ ปัญหาใหญ่ถือว่า "แก้แล้ว" ตอนที่มี proof ไม่ใช่ตอนที่มีคนอธิบายได้ว่าทำไมมันจริง

วงการไม่ได้มองแค่ proof เสียทีเดียว วารสารตีกลับ paper ที่เขียนแย่ แม้ทฤษฎีบทข้างในจะสำคัญ แต่ระบบเครดิตยังผูกกับ proof เป็นหลัก พอ model หาคำตอบได้ก่อน คนที่ไล่โจทย์อยู่จึงรู้สึกเหมือนเหลือแค่ตามเก็บกวาด

**ผลคือ:** พอเครื่องสร้าง proof ได้ ตัวแทนนี้ก็แยกออกจากสิ่งที่มันเคยแทน

## เป้าหมายจริงคือทฤษฎี

ส่วนนี้คือใจความของข้อเสนอ ถ้า proof เป็นวัตถุดิบ แล้วอะไรคือของที่มีค่า

3B1B ให้น้ำหนักกับการสร้างทฤษฎี (theory building) คือหาว่าอะไรเรียบง่ายร่วมกันในหลาย proof แล้วร้อยเป็นกรอบคิดใหม่ ตัวอย่างที่เขายกคือ สิ่งที่มีค่าไม่ใช่ proof ว่าสมการกำลังห้าแก้ด้วยสูตรไม่ได้ แต่เป็น group theory ที่ Galois เริ่มไว้ ซึ่งใช้กันต่อมาอีกหลายศตวรรษ

อีกตัวอย่างคือ Navier-Stokes เขาบอกว่าไม่ได้สนใจ proof ในตัวมันเอง ถ้ามีคนเข้าใจไอเดียข้างใน แล้วต่อเป็นทฤษฎีที่ต่อกันเป็นเรื่องเดียว ก็ให้รางวัล Millennium Prize คนนั้น

> "The proof is just data, it's like giving me more digits of π."

**ได้อะไร:** วัดผลงานจากความเข้าใจที่ส่งต่อได้ ไม่ใช่จากการเป็นคนแรกที่ได้ proof

## ผลต่อวิธีทำงาน

วิดีโอให้คำแนะนำที่ใช้ได้ทันทีหลายข้อ

- **ใช้ model เหมือนเฉลยท้ายเล่ม** ยังทำโจทย์เอง แต่ถ้าติดก็เปิดดูได้ จะได้ไม่ต้องเดินในที่ที่ไม่มีใครเคยไปทุกครั้ง
- **ถามก่อนว่าขาดอะไร** บางครั้งขาด proof อีกชิ้น ถาม model ก็ได้ แต่บ่อยครั้งควรปิด laptop เขียนความเข้าใจของตัวเอง แล้วถามว่าอะไรขวางไม่ให้เกิดทฤษฎีที่ลึกกว่านี้
- **ให้เครดิตคนต้นทาง** proof จากเครื่องมักใช้ idea จากงานตีพิมพ์ของคน และ model ยังไม่ให้เครดิตเองโดยอัตโนมัติ
- **ฝึกนำเสนอด้วยปาก** ถ้าเครื่องเขียนอธิบายได้ดีด้วย การพูดให้คนอื่นเข้าใจและสนใจจะเป็นสิ่งที่วัดความเข้าใจของคนได้ "The machine can't understand it for you"
- **เปลี่ยนวิธีวัดผลงานวิชาการ** เขามองว่าดี เพราะ proof "has probably been overvalued for decades"

## ต่างจาก Quality Proxy Collapse ยังไง

ส่วนนี้เป็นข้อสังเกตของ wiki วิดีโอไม่ได้พูดถึงงาน software

ทั้งสองเรื่องเป็นกรณีที่ตัวแทนคุณภาพแบบเดิมใช้ไม่ได้ แต่พังคนละแบบ

| | [[quality-proxy-collapse\|Quality Proxy Collapse]] | Proof as Raw Data |
|---|---|---|
| ตัวแทนเดิม | หน้าตาเรียบร้อย, test ผ่าน, prose ลื่น | มี proof |
| สิ่งที่มันเคยบอก | มีคนตั้งใจทำและเข้าใจระบบ | มีคนเข้าใจคณิตศาสตร์ตรงนั้น |
| ทำไมใช้ไม่ได้แล้ว | AI สร้างหน้าตาดีได้ ทั้งที่ข้างในอาจไม่ดี | proof ยังถูกจริง แต่ไม่ได้แปลว่ามีคนเข้าใจ |
| ทางออกที่เสนอ | verifier, evidence, process trace | theory building, oral presentation |

ในกรณีของ proof ตัวงานยังดีอยู่ สิ่งที่หายไปคือข้อมูลว่าใครเข้าใจ ภาพนี้คล้าย [[comprehension-debt|comprehension debt]] ในงาน software คือ code ที่ทำงานได้ไม่ได้แปลว่าทีมเข้าใจระบบ และคล้าย [[code-is-free|code is free]] ตรงที่พอการสร้าง artifact ถูกลง คุณค่าก็ย้ายไปอยู่ที่ความเข้าใจและ judgement

**ผลคือ:** ถ้า artifact ถูกต้องแต่สร้างได้ฟรี ให้วัดคนจากสิ่งที่เขาทำกับ artifact นั้น ไม่ใช่จากการมีมัน

## คำถามที่ยังเปิดอยู่

- ถ้าไม่ใช้ proof เป็นเกณฑ์ ใครจะตัดสินว่าทฤษฎีไหนมีค่า และจะวัดยังไงไม่ให้กลายเป็นเรื่องรสนิยมของกรรมการ
- วิดีโอไม่ได้พูดว่าใครจะตรวจว่า proof จาก model ถูก ถ้า proof ยาวและอ่านยาก การมองว่าเป็นข้อมูลดิบต้องพึ่งว่ามีคนหรือเครื่องตรวจได้
- 3B1B คาดว่าคำอธิบายจาก model จะดีขึ้น ถ้าเป็นจริง การพูดต่อหน้าคนจะยังแยกคนที่เข้าใจออกจากคนที่ท่องคำอธิบายของ model ได้หรือไม่
- ข้อเสนอนี้สมมติว่าเครื่องยังสร้างทฤษฎีไม่ได้ ถ้าสร้างได้ด้วย วิดีโอบอกว่าคุณค่าจะเหลือที่การเรียน การสอน และความสุขจากการทำเอง (ดู [[career-value-stack]])
