# Agent Memory Hierarchy / แบ่งชั้นความจำให้ค้นง่ายและตรวจย้อนกลับได้

[[anthropic|Anthropic]] บริษัทผู้สร้าง Claude เสนอให้มองความจำของ agent เป็นหลายชั้นใน [[components-of-agent-memory-anthropic|The Components of Agent Memory]] เราเก็บประวัติไว้ตรวจย้อนกลับ จดบทเรียนที่น่าจะใช้ซ้ำ สร้างแผนที่ความรู้ และเลือกเพียงบางเรื่องมาโหลดให้ทุกครั้ง

## แต่ละชั้นตอบคนละคำถาม

การแบ่งชั้นช่วยให้เลือกได้ว่าอะไรควรติดตัว agent ไปทันที และอะไรค่อยเปิดอ่านเมื่อจำเป็น

| ชั้น | คำถามที่ช่วยตอบ | ตัวอย่าง |
|---|---|---|
| Transcripts | ตอนนั้นเกิดอะไรขึ้นในบันทึก? | คำขอ ผลจาก tool และขั้นตอนที่ลอง |
| Memory notes | มีอะไรควรเก็บไว้ใช้รอบหน้า? | บทเรียนที่ตรวจแล้ว แผน และข้อควรระวัง |
| Memory representations | เรื่องนี้เชื่อมกับอะไร และต้องไปอ่านที่ไหน? | [[llm-knowledge-bases\|wiki ที่เชื่อมหน้าเกี่ยวข้องไว้]] |
| Injected context | ก่อนเริ่มงานทุกครั้งควรรู้อะไร? | เป้าหมายสำคัญกับดัชนีสั้น ๆ |

ชั้นบนใช้เริ่มงานได้เร็ว แต่ยิ่งสรุปมากก็ยิ่งต้องมีทางกลับไปหาที่มา การค้นประวัติหรือต้นฉบับจึงยังจำเป็น **ผลคือ:** agent ไม่ต้องเลือกระหว่างอ่านทุกอย่างกับเชื่อบทสรุปอย่างเดียว

## การทบทวนย้ายข้อมูลได้ทั้งขึ้นและลง

[[dreaming|Dreaming]] คือการกลับมาจัด memory นอกงานหลัก มันอาจแก้ note จาก transcript รวมบันทึกเป็นหน้า wiki หรือยกเรื่องสำคัญขึ้นมาไว้ใน context ตอนเริ่ม session ถ้าชั้นบนยาวเกินไป ก็ย้ายรายละเอียดลงแล้วเหลือลิงก์ไว้แทน

ตัวอย่างที่นำกรอบนี้มาใช้กับวิกินี้ได้: `hotcache.md` เก็บเรื่องที่ควรรู้ก่อน ส่วนหน้า concept อธิบายรายละเอียดและโยงไป source ที่มีลิงก์ต้นฉบับ นี่เป็นการเทียบของ wiki ไม่ใช่ข้ออ้างว่าบทความตรวจระบบนี้แล้ว และ `raw/` ใน repo นี้ก็เป็นเอกสารต้นทาง ไม่ใช่ transcript ของ agent

**ได้อะไร:** จำกัด [[instruction-budget|ปริมาณคำสั่งที่ต้องรับพร้อมกัน]] โดยยังเก็บความรู้ละเอียดไว้ค้นต่อ

## ไม่ใช่การแบ่งตามชนิดของความรู้

[[agent-memory-types|Semantic, episodic และ procedural memory]] แบ่งว่าเก็บข้อเท็จจริง เหตุการณ์ หรือวิธีทำงาน ส่วน hierarchy แบ่งว่าความรู้นั้นถูกจัดและส่งให้ agent อย่างไร กฎวิธีทำงานหนึ่งข้อจึงอยู่ได้ทั้งใน note หน้า wiki และ context ที่โหลดล่วงหน้า

[[agent-memory-filesystem|Memory แบบ filesystem]] บอกวิธีเก็บและแก้ไฟล์ ส่วน [[compaction|compaction]] ย่อประวัติเพื่อให้งานเดิมเดินต่อ ทั้งสองอย่างเกี่ยวข้องกับ hierarchy แต่ไม่ได้ตอบคำถามเดียวกัน

**ผลคือ:** เลือกชนิดข้อมูล ที่เก็บ และวิธีนำกลับมาใช้แยกกันได้

## สิ่งที่ควรวัด

ข้อเสนอสำหรับตรวจระบบจากกรอบนี้ ไม่ใช่เกณฑ์มาตรฐานที่บทความรับรอง:

- บันทึกข้อเท็จจริงกับข้อสันนิษฐานแยกกันหรือยัง และย้อนหาหลักฐานได้ไหม?
- agent อ่าน memory แล้วทำงานดีขึ้นจริงหรือแค่มีไฟล์เพิ่ม?
- wiki ช่วยเชื่อมหลายแหล่ง หรือเขียนซ้ำจนใหญ่กว่าต้นฉบับ?
- เมื่อข้อมูลเปลี่ยน ใครแก้ [[memory-drift|ความจำที่ผิดหรือหมดอายุ]] และแก้ถึงชั้นที่โหลดทุกครั้งหรือยัง?
- เมื่อรวมต้นทุนสร้าง ทบทวน และตอบคำถามแล้ว ยังประหยัดเวลาหรือ tokens หรือไม่?
